1.개요

터보워크는 2026년 10월부터 Kaggle Name That LLM 대회에 참가하고 있다. 학습 데이터는 질문 150개에 대한 18개 AI 모델의 답변 2,699개다. 숨은 시험에는 학습 데이터에 없는 질문이 나온다.

이 기록의 특징은 무엇이 자기 실력이고 무엇이 남의 공개 코드인지 구분해서 적는다는 점이다. 현재 최고 점수 0.695는 다른 참가자가 공개한 노트북을 코드 수정 없이 재현한 점수다. 직접 만든 모델의 최고는 0.297이고, 공개 노트북 위에 직접 덧붙인 개선은 모두 점수를 떨어뜨려 쓰지 않았다.

3.순위

0.651 시점 순위는 상위 약 12%였다. Kaggle 화면에서 대표가 직접 확인한 값이며, 공식 API로 다시 조회한 값은 아니다. 0.695 시점의 순위는 아직 기록하지 않았다. 참고로 공개 리더보드 1위는 11월 14일 기준 약 0.771이다.

4.연구하고 순위에 임하는 방식

대회 작업도 레드 샌드위치 하네스 위에서 한다. Step마다 명세를 쓰고, 다른 회사 AI의 검수를 받고, 실패는 실패 랙에 남긴다. 128개 Step 기록이 모두 남아 있다.

4.1.사전 등록

모든 시험은 결과를 보기 전에 방법과 채택 기준을 파일로 고정하고 해시(SHA)를 남긴다. 예: "공개 점수가 0.693보다 높을 때만 채택", "balanced accuracy가 0.01 이상 오를 때만 채택". 기준에 못 미치면 비슷한 변형을 계속 시도하지 않고 버린다. 리더보드를 보며 설정을 맞추다 보면 숨은 시험에서 점수가 무너지기 때문이다.

4.2.검증 설계

  • 질문 단위 5겹 교차검증(GroupKFold). 같은 질문의 답이 학습과 검증에 나뉘어 들어가면 점수가 부풀려지므로 질문 단위로 나눈다.
  • 나눈 결과(folds.npy), 행·정답·fold의 대응표, 확률 파일을 모두 해시로 보존한다.
  • 같은 검증 결과를 보며 길이·seed·epoch·블렌드 비율을 고르지 않는다. 중첩 교차검증도 하지 않는다.

4.3.원본 잠금과 예산

  • 최고점 노트북·소스·가중치는 해시로 동결하고 덮어쓰지 않는다. 22개 파일 대조 불일치 0.
  • GPU 실행은 Kaggle T4×2, 9,200초 작업 / 10,800초 강제 상한. 새 GPU 실행은 범위와 예산을 먼저 정한다.
  • 유료 API는 견적을 먼저 낸다. 지금까지 쓴 유료 API 비용은 0원이다.

4.4.멈추는 규칙

숨은 시험에서 같은 계열 변형이 2번 연속 실패하면 멈추고 사람이 판단한다. AI가 같은 실수를 반복하며 하루 제출 횟수(5회)를 써 버리는 것을 막기 위해서다.

5.단계별 접근

  1. 자체 기준선 (10.26~28): CPU로 LightGBM, LightGBM+CatBoost. 0.297에서 멈춤.
  2. 공개 GPU 기준선 재현 (10.27~29): Llama 3.1 8B, Qwen 계열 LoRA, DeBERTa를 묶은 공개 노트북을 재현. 모델 접근 승인 대기로 하루 넘게 막혔다가 해제.
  3. 검증 연구 (10.29~11.05): 후보 모델을 같은 5겹 분할에서 비교. UltraBERT 0.392, head-tail 0.382, ModernBERT 0.287 등 모두 교체 기준(+0.005, 손실 악화 없음, 자원 1.1배 이하)에 못 미쳐 탐색 중단.
  4. 숨은 시험 실패 진단: 공개 시험 3행 통과가 숨은 시험 완주를 보장하지 않음을 확인. 빈 어휘, 확률 합이 1을 아주 조금 넘는 부동소수점 문제 등 경계 결함을 찾아 고침.
  5. 대리 평가 검증 (Step 109~118): 검증에서 +0.012였던 변경이 실제로는 −0.018. 그 대리 평가를 선별에 쓰지 않기로 기록.
  6. 공개 노트북 재현 (Step 119~128): 명령줄로 복사하면 연결 자료가 최신판으로 바뀌어 실패. 화면에서 버전을 고정해 복사해야 재현된다는 것을 확인. 9시간 제한을 넘지 않도록 시간 예산 장치가 있는 노트북을 고름.

6."값싼 재료" 시험 8개

공개 데이터만으로 학습하고 대회 학습 데이터로 채점하는 시험대를 따로 만들어, 비용이 거의 들지 않는 아이디어 8개를 사전 등록 기준으로 시험했다.

7.배운 것

  • 공개 시험 통과는 숨은 시험 완주를 뜻하지 않는다.
  • 대리 평가의 데이터 구조가 실제와 다르면 방향까지 거꾸로 나온다.
  • 공개 노트북은 점수가 붙은 버전을 화면에서 버전 고정으로 복사해야 재현된다.
  • 시간 초과 위험은 코드에 시간 예산 장치가 있는지로 미리 가린다.
  • 복사로는 1등을 할 수 없다. 다음 개선은 0.695 위에 얹을 자체 아이디어를 결과 보기 전에 고정하고 시험한다.

8.다음 계획

0.695 노트북 위에 얹을 자체 개선안을 사전 등록하고 시험한다(Step 129). 결과는 이 문서에 그대로 적는다. 오르든 떨어지든 적는다.
