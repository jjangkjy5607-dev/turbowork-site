Red-Sandwich Harness

Our core method, published as an open specification on GitHub. AI-generated code can pass a happy-path example while missing edge cases or drifting from the agreed spec. The harness wraps every build step between two deterministic gates and lets an adversarial reviewer attack it.

Top breadSpec-Lock TDD GateInput/output contracts are fixed before implementation; execution is blocked when they fail.
FillingAST Pure Units≤ 35 logic lines per function, ≤ 200 lines per file, cyclomatic complexity ≤ 5 — checked on every edit.
Bottom breadStrict IsolationFresh state per fold and per step; only the exact tree that passed audit is committed.
Red-Team Auditor

An independent model attacks the implementation with concrete counterexamples.

Missing values, extreme inputs, shape mismatches and leakage paths. Each finding is reproduced locally, then locked in as a test.

Only an explicit PASS from the executable gates admits the next stage — never the coding agent's own report.

Grown into the v6.6 deterministic harness

The sandwich now runs unattended across all our projects: one step per AI session, two separate audits, automatic retries.

Where we hit the wall

Everything above was built and run on one desktop: RTX 3060 (12 GB), i5-12400F, 32 GB RAM. Code is fine; graphics are not. A lip-sync model alone needs ~11 GB, so heavy jobs queue one at a time through our own memory guard. With cloud GPUs and credits we would render full-length virtual-singer videos, batch seller videos, and generate 3D assets at full quality.
